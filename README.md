# Календарь педагога

Веб-приложение для формирования календарного плана DOCX на основе учебно-тематического плана (УТП) и образовательной программы.

Приложение локально разбирает УТП и образовательную программу, сопоставляет темы, распределяет часы по 36 неделям учебного года Y–(Y+1), заполняет поля занятий (rule-based и опционально через OpenAI) и формирует готовый DOCX для однократного скачивания. Для 2026–2027 сохраняется утверждённый календарный профиль; другие годы получают базовую сетку без копирования каникул.

## Запуск

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

После запуска откройте адрес, показанный Streamlit (обычно `http://localhost:8501`).

Для AI-генерации полей занятий задайте переменную окружения `OPENAI_API_KEY` в файле `.env` или в системе.

## Пользовательский сценарий

1. Загрузить УТП (обязательно) и образовательную программу (рекомендуется).
2. При необходимости загрузить шаблон календарного плана организации (DOCX).
3. Проверить учебный год Y–(Y+1): подставится из документов или указывается вручную.
4. Нажать **Проверить документы** — просмотреть анализ, расписание и rule-based поля.
5. Опционально включить **Дополнить поля занятий через OpenAI**.
6. Нажать **Сформировать календарный план** — DOCX проходит structural + visual QA.
7. Скачать результат одной кнопкой; файл не сохраняется на сервере.

## Структура

```text
app.py                         точка запуска Streamlit
src/calendar_pedagoga/         прикладные модули
  parsing.py                   разбор УТП DOCX
  validation.py                проверка арифметики и согласованности УТП
  program_parsing.py           чтение программ DOCX и безопасная конвертация DOC
  matching.py                  детерминированное сопоставление УТП и программы
  scheduling.py                календарная сетка и распределение часов
  content_generation.py        Content Model и связи строк с источниками
  lesson_content.py            строгое заполнение полей занятий без ИИ
  lesson_resolution.py         объединение rule-based и AI-полей
  ai_preparation.py            JSON-контракт AI-генерации
  ai_provider.py               провайдер OpenAI Responses API
  docx_generation.py           сборка итогового DOCX
  docx_qa.py                   structural + visual QA DOCX
  pipeline.py                  сквозная оркестрация upload → DOCX
  ui.py                        интерфейс Streamlit
  transient_documents.py       жизненный цикл in-memory документов
tests/                         автоматические проверки (unit, pipeline, DOCX QA)
references/                    неизменяемые исходные и эталонные документы
```

|---|---|
| `Календарный_план_КЛЮЧ_2026-2027_с_датами.docx` | Готовый календарь «КЛЮЧ»: эталон структуры и оформления |
| `УТП КЛЮЧ 2 г. 2ч.docx` | УТП «КЛЮЧ»: исходные данные |
| `Программа КЛЮЧ.DOC` | Программа «КЛЮЧ»: источник содержания |
| `УТП ТП 3г. 2ч.docx` | УТП «Туристы-проводники», 3-й год: QA без программы |
| `Календарный_план_Туристы_проводники_3_год_2026-2027_Верно.docx` | Контрольный эталон результата (только QA, не источник содержания) |

Файлы в `references` предназначены только для чтения и не должны изменяться приложением.

## Политика хранения пользовательских документов

Сервис не является хранилищем документов. УТП, образовательные программы, шаблоны организации, содержимое документов и готовые файлы не записываются в БД или постоянное файловое хранилище.

Жизненный цикл операции: загрузка → проверка → обработка → формирование → однократная передача результата пользователю → очистка. Исходники и результат существуют только в памяти текущей изолированной операции.

## Ограничения

- учебный год задаётся как Y–(Y+1); сетка 36 недель;
  профиль исключений 2026–2027 не копируется на другие годы;
- без образовательной программы содержание занятий остаётся пустым, AI недоступен;
- «Туристы-проводники» без программы — только ограниченный QA-референс;
- нет базы данных, авторизации, оплаты и облачного деплоя.

## Правила разбора УТП

- строки разделов и тем хранятся отдельно;
- прочерки в часах трактуются как ноль;
- для каждой темы проверяется равенство «Всего = Теория + Практика»;
- сумма тем сверяется с итоговой строкой таблицы;
- годовой объём сверяется между информационной справкой, недельной нагрузкой и итогом таблицы;
- противоречия показываются как предупреждения и не исправляются автоматически.
