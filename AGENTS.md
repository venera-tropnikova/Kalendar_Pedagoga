# Работа с проектом «Календарь педагога»

## Перед началом
- Проверить рабочую папку: D:\Kalendar_Pedagoga.
- Прочитать PROJECT_PASSPORT.md и PROJECT_RULES.md.
- Проверить ветку, git status и релевантный diff.
- Существующие dirty-изменения считать чужими: не перезаписывать,
  не откатывать, не очищать и не включать в свою задачу.

## Выполнение
- Одна задача — одна логическая цель и минимальная область изменений.
- Сначала определить затронутые модули, риски и критерии проверки.
- Запрос на анализ не разрешает изменения.
- Если пользователь требует предварительного подтверждения,
  остановиться после плана.
- Не выполнять несвязанный рефакторинг и улучшения.
- Постоянные правила применять без повторения их пользователем.
- Не требовать нескольких агентов для обычной задачи.

## Защита решений
- Утверждённые решения из паспорта не пересматривать самостоятельно.
- Исправлять реализацию без изменения утверждённой концепции.
- При противоречии или существенном риске сообщить доказательства
  и запросить решение до изменения инвариантов.
- Не считать существование кода подтверждением его утверждения.

## Проверка и завершение
- Проверять результат по PROJECT_RULES.md соразмерно риску.
- Указывать фактические проверки и ограничения.
- Различать VERIFIED, PARTIALLY VERIFIED и NOT VERIFIED.
- PASS означает, что необходимые проверки задачи выполнены и прошли;
  это не заменяет пользовательскую приёмку, если она требуется.

## Обязательная фиксация после PASS
После завершения логической задачи с PASS самостоятельно инициировать
цикл фиксации по действующему глобальному DEVELOPMENT_STANDARD пользователя.

Применять стандарт без дублирования его процедуры здесь.
Не завершать работу молча на состоянии «проверено, но не зафиксировано»:
выполнить предусмотренный стандартом следующий шаг либо явно
обозначить препятствие. Подтверждения коммита и push не подменять.

Для задач без изменений файлов коммит не требуется.
Отдельный TASK_LOG.md не вести.
