# Правила проекта «Календарь педагога»

## Источники и данные
- Сохранять связь результата с исходными темами и документами.
- Не придумывать отсутствующие сведения, часы и содержание.
- Не исправлять противоречия источников молча.
- Различать исходные документы, шаблоны и контрольные эталоны.
- Эталон результата не использовать как источник учебного содержания.
- Не изменять references и пользовательские исходники.
- Не сохранять пользовательские документы и результаты постоянно.

## CE2
- Основной сценарий детерминированный, без AI и внешних AI-вызовов.
- Сохранять контракт между моделью содержания, разрешением полей
  и DOCX.
- Не переключать CE2 на прежний движок без отдельного согласования.
- Не добавлять предметные исключения только ради одного примера,
  если они искажают общие правила.

## Расписание
- Сохранять порядок тем и разделов УТП.
- Сверять общий объём, теорию, практику и недельную нагрузку.
- Не терять и не дублировать часы при переносах между неделями.
- Сохранять утверждённые даты, перерывы и подписи месяцев
  профиля 2026–2027.
- Не копировать каникулы и разрывы 2026–2027 на другие годы.
- Не расширять профиль исключений 2026–2027 автоматически.

## Template-first DOCX
- Использовать выбранный поддерживаемый шаблон как основу документа.
- Сохранять утверждённые колонки, оформление и правила разбиения.
- Проверять шаблон организации до генерации.
- Не подменять неподдерживаемый шаблон молча:
  показать причину и предложить явный выбор стандартного.
- Не менять оформление ради обхода ошибки содержания.
- Не выдавать документ с блокирующими QA-ошибками.

## Нормативная проверка
- Использовать версионируемый реестр с источниками и сроками действия.
- Обновлять нормативные сведения только после проверки источников.
- Различать «проверено», «предупреждение» и «не проверено».
- Отсутствие данных не считать успешной проверкой.
- Не представлять ограниченную проверку как полное подтверждение
  нормативного соответствия.
- Не менять часы, расписание, CE2 или DOCX по результатам проверки.
- Не заменять выбранную нормативную версию без явного выбора.

## Локальный запуск
- Запускать проект только на http://localhost:8501.
- Не выбирать запасной порт.
- Перед остановкой процесса определить, какому проекту он принадлежит.
- Не завершать чужой процесс.
- Проверять HTTP 200 и принадлежность приложения текущему проекту.
- HTTP 200 не считать доказательством исправности генерации DOCX.

## Проверка изменений
- Выбирать targeted tests по затронутой области.
- Для изменения логики проверять критический сценарий вокруг неё.
- Для CE2 и расписания проверять сохранение содержания и часов
  на релевантных контрольных примерах.
- Для нормативного контура проверять статусы, неполные данные
  и отсутствие влияния на генерацию.
- Для UI проверять фактический браузерный сценарий и ошибки выполнения.
- Для DOCX выполнять структурную проверку, render и просмотр всех
  изменённых страниц; проверять переполнение, переносы, объединения,
  подписи, читаемость и соответствие эталону.
- При изменении общего механизма проверять релевантные сценарии
  «КЛЮЧ» и «Туристы-проводники», стандартный и организационный шаблоны.
- Не заявлять о проверках, которые не выполнялись.

## Итоговый статус
- VERIFIED — необходимые проверки выполнены и прошли.
- PARTIALLY VERIFIED — перечислены невыполненные проверки и риски.
- NOT VERIFIED — необходимая проверка не выполнена; не писать «готово».

## Гигиена
- Не включать временные рендеры, логи, кэши и пользовательские
  документы в Git.
- Удалять только собственные однозначно временные артефакты.
- Не очищать существующие dirty-файлы и неизвестные результаты.
- Обновлять только документацию, затронутую согласованной задачей.
