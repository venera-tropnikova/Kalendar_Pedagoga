# Этап C — универсальное подтверждение структуры

## Граница этапа

База: `67675729e94dc67ea3315f15d2f6e271f14ffda4` (этап B).
Реализация добавлена в `calendar_pedagoga.ingestion_confirmation`. A, B и production-код
не изменяются. Существующий `program_structure_confirmation.py` зависит от legacy
parser, matching и downstream, поэтому не включён в новый контур.

В C нет календаря, недель, генерации содержания, RESULT/CONTROL, DOCX и адаптера
production `ConfirmedStudyPlan`. Завершённый `Session` — подтверждение структуры;
преобразование его плана в downstream-контракт остаётся этапом D.

## Данные и сохранность

- `ReviewModel` содержит исходные `StructuralDocument` целиком, включая исходные
  `ExtractedDocument`. Ничего не копируется в урезанный доменный объект.
- `Assessment` — вычисляемое состояние: выбранные год/источник/план, варианты,
  границы, группы связей и точные расхождения часов.
- `Session` хранит неизменяемый журнал `Event`: действие, канонический JSON,
  fingerprint, evidence, исходные SourceSpan. Для явного действия confidence=1
  означает достоверность факта подтверждения, а не правильность мнения человека.
- Подтверждения — отдельный слой. Выбор границ или колонок не удаляет альтернативы,
  UNRESOLVED, исходные строки, ожидаемые результаты, нормативные таблицы или часы B.
- Fingerprint включает SHA исходников, версии схем и всю структурную модель B.
  Имена файлов не участвуют. Изменение исходника или интерпретации отменяет все
  активные решения; прежние события остаются в архиве с evidence.
- `save/restore` использует JSON и заново проверяет переходы. Сохранённое событие
  не может подтвердить текущий конфликт часов. Постоянное хранение не добавлено.

## Общие переходы

Обнаружение состояния повторяется после каждого действия. Порядок разрешения:
год → источник → план → колонки → часы → границы → связи → итоговое подтверждение.
Это порядок зависимостей: последующие неопределённости остаются в исходной модели,
а не считаются автоматически решёнными.

| Состояние | Действие | Условие перехода |
|---|---|---|
| VALID | «Да, продолжить» | Одно действие завершает подтверждение |
| YEAR_AMBIGUOUS | Выбор года | Один из вариантов; при отсутствии маркера — явный положительный номер |
| SOURCE_CONFLICT | Выбор источника | Показаны планы, годы и позиционные различия; план другого года выбрать нельзя |
| PLAN_AMBIGUOUS | Выбор таблицы | Выбран существующий кандидат; одинаковые варианты не схлопываются |
| COLUMN_AMBIGUOUS | Назначения колонок и строки шапки | Обязательны уникальные название и всего; B повторно извлекает строки по явной схеме |
| HOURS_CONFLICT | Исправленный исходник либо исправление ошибочно выбранной структуры | Продолжение запрещено, пока точный пересчёт не пройдёт |
| CONTENT_BOUNDARY_AMBIGUOUS | Выбор областей либо начала/конца | Начало включено, конец исключён; области не пересекаются и не захватывают другой год |
| BINDING_AMBIGUOUS | Один групповой экран | Все спорные темы получают явно выбранные разделы своего года |

`Исправить` открывает только выбранный пользователем вид проверки и отменяет
зависящие от него ответы. Выбор новых колонок или плана отменяет подтверждения
связей, смена года — все зависимые решения. Изменение границ отменяет связи.
Неизменившиеся независимые решения не спрашиваются повторно.

Один physical table с альтернативными ColumnMapping требует уточнения колонок,
а разные таблицы — выбора плана. Неизвестная схема не отвергает документ:
таблицу можно явно отметить и сопоставить колонки. Нормативные таблицы не
становятся кандидатами автоматически из-за чисел или согласованной арифметики.
Если таблиц нет, требуется новый входной план; это не ошибка «не программа».

## Источники и арифметика

После подтверждения приоритет: внешний план → валидный встроенный → явно
предоставленный ручной ввод. Расхождение источников требует выбора, в том числе
при разных годах. Неопределённые схемы не объявляются эквивалентными.

`build_model(program, external=None, manual=None)` принимает результаты A/B.
`manual` означает явно предоставленный и нормализованный ввод; C не создаёт
ручной план из недостающего текста и не добавляет отдельный редактор ручного ввода.
Валидный встроенный план не требует внешнего файла.

B `arithmetic` вызывается повторно над выбранными строками; расчёт использует
Fraction, без float. Пустое значение, ноль и тире сохраняются. Неизвестные числа,
неясное выравнивание, отрицательные часы и отсутствие единственного итога
блокируют продолжение. Для определённых чисел UI показывает документ, расчёт
и точную разницу `расчёт − документ`.

Подтверждённые колонки используют тот же B `_rows`/`arithmetic`, а не новый parser.
Эта внутренняя зависимость покрыта совместным прогоном A+B+C. B-объект не меняется.
Новые сопоставления тем алгоритмически не создаются. Можно переиспользовать только
поддержанную B-связь с неизменными исходными строками; остальные связи выбирает
педагог. План и содержание с разными указанными часами показываются на экране
связей, их значения сохраняются. Подтверждение связи не исправляет эти числа.

## Единый интерфейс

Обычный экран: «Мы нашли: год обучения; учебный план — темы и часы; содержание —
разделы. Всё верно?»; кнопки «Да, продолжить» и «Исправить».
SOURCE, confidence, ColumnMapping и YearScope пользователю не показываются.
Расширенные экраны открываются по состоянию либо по явной просьбе исправить.
Признанные значения колонок уже заполнены; подтверждённые связи отсутствуют
в обычном групповом списке спорных связей.

Renderer один: `ui.render_confirmation`. Изолированный QA entry point:
`tools/ingestion_confirmation/app.py`. По умолчанию `SHADOW_ENABLED=False`;
entry point тоже выключен без явного `KP_INGESTION_CONFIRMATION_SHADOW=1`.
Production не импортирует этот пакет. Документы QA-контейнера хранятся только
в текущей Streamlit-сессии; глобальный cache пользовательских документов не создан.

## Критерии проверки

- Любой VALID завершается одним подтверждением.
- Любой HOURS_CONFLICT блокирует подтверждение, включая повтор событий из JSON.
- Все восемь состояний вызываются структурными мутациями и проверяются в одном UI.
- При смене входа/структуры старые решения не действуют; без смены сохраняются.
- Ни одна ветвь не меняет и не удаляет A/B, source spans и исходные противоречия.
- Property tests меняют колонки, многострочную/объединённую шапку, номер года,
  суммы часов, число кандидатов и границы. Отдельно проверены точные дроби,
  чужой год, неизвестная таблица, изменение значений после выбора колонок.
- Corpus берётся только из общего manifest A. Одна параметризованная функция,
  общий обход всех ветвей года/плана, один набор инвариантов и один renderer.
  Нет пофайловых ожидаемых состояний/текстов и тематических исключений.
- PASS C не подтверждает за педагога спорные решения и не разрешает этап D.
